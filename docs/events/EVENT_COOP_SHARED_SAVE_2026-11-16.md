## 2. 活动地图 DECK / MEDAL 之后 BACK 无法退出

- 现象（26.11.14）：协力作战 P1 / P2 → 出擊 → 活动地图 → DECK → BACK 回到地图后，地图的 BACK 每次都重新进入地图。原生路径无此现象。
- 原因：活动地图（场景 160）的 BACK 以 `app+0xb16c` 为目的场景，基地“出擊”写入 72（女教官基地）。底栏按钮的写法分两类：POW、OPTION、SHOP 按下时取走该字段并清零；DECK、MEDAL 按下时把它写为 158（子画面返回活动地图用），子画面返回时取走清零。字段为 0 时原生 BACK 的去向：原生路径（合作路由）实测为 72，PVZ EVENT（经典路由，第 374 节）为 27（主菜单）。第 374 节的写回逻辑把在地图上见到的任何非零值记为返回目的，DECK、MEDAL 写入的 158 因此被记下，回到地图时写回，BACK 的目的地成为地图自身。该逻辑对全部经 EventMSD 场景运行的活动生效：修正前已复现协力作战 P2 的 DECK、P1 的 MEDAL 与 PVZ EVENT 的 MEDAL。
- 修改（`NativeEventMap.update`）：只记离开基地后的第一个值，且不记地图场景号（158 / 159 / 160）；写回条件不变。
- 结果：协力作战 P1 / P2 与 PVZ EVENT 中，DECK、MEDAL、POW 之后地图 BACK 均回到女教官基地，基地 BACK 回到活动浏览页。
- 既有行为（未改）：活动地图的 OPTION、SHOP 为原生直接转到主菜单的对应子页并结束活动上下文。

## 4. 积分字段的归属（`event_trial.py`）

- 原生字段平时即共用积分。进入协力作战时直接采用字段的现值，离开时字段保持。
- 进入其他活动（各有独立货币或无货币）时，该活动的货币占用原生字段：进度文件写入 `survival_point_owner`（占用者）与 `baseline_survival_currency`（共用积分）；离开时写回共用积分，以 `WriteMainSaveDataExe` 当场写入原生存档，再清除占用标记。
- 在其他活动内退出游戏：下次启动到主菜单（场景 28 状态 1）时按占用标记恢复共用积分。
- 旧进度的一次性合并（进度文件无 `survival_point_shared` 时，于首次进入活动时执行）：共用积分取原生字段与 P1 / P2 原有积分中的较大者；原生字段与某个其他活动的货币相同（上次在该活动内退出）时改取旧基准值。两份积分此前分开记录，上次在协力作战内退出时相等，取较大者不会重复计入。

## 5. 通关记录的互补（`event_native_map.py`）

- `merge_native_records`（进入协力作战时，`NativeEventMap.enable` 中、地图钩子生效之前）：原生存档已通关的小关写入活动进度（胜场至少为 1，时间取较短者）；活动进度有胜场而原生通关位为空的小关，以原生 `AddStageClearSaveData` 补写。
- `save_result`：P1 / P2 的胜利当场写原生通关位。原生结算在这一场合读到的是宿主已登记的通关（地图钩子 `map_stage_clear`），不写通关位，只写时间。
- 由活动进度决定的条件（例：通关 61054 后开放 Cabrakan 的购买，`unit_rewards.json` 的 `stage_win`）因此计入原生路径的通关。
